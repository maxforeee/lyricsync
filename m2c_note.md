# M2.2 — Fixed highlight anchor (m2c)

## What changed
Removed the M2.1 "only scroll when the current line leaves the visible range or nears the bottom edge" optimisation in `LyricsList` (`LyricsScreen.kt`): the `LaunchedEffect(currentIndex, followEnabled)` now springs the list to the anchor on **every** `currentIndex` change while follow is enabled, so the highlighted line stays fixed at 35% viewport height and the lyrics lift up under it one line at a time. Per the addendum, the scroll uses `spring(stiffness = Spring.StiffnessLow, dampingRatio = Spring.DampingRatioMediumBouncy)` for a gentle Apple Music-style lift, and `LyricRow` gained a `currentEmphasis` `Animatable` that snaps to 0.9 and animates to 1.0 over `tween(300)` when a line becomes current, multiplying its scale and alpha so the incoming line grows/brightens into place instead of snapping; neighbouring lines keep their existing 250ms arc scale/alpha/tilt tweens, which run in sync with the scroll. Everything else from M2.1 is untouched: the `lastAutoScrollTarget` guard still avoids restarting an in-flight animation for the same target, a manual drag still sets `followEnabled=false` (which restarts the keyed `LaunchedEffect`, cancelling any in-flight auto-scroll) until "Resume follow" is tapped, and the arc transform, fades, 35% anchor padding and transparent status bar are unchanged. No changes to lyrics fetching, the ViewModel, menu items, or workflows.

## What is NOT done
- No local build/test/run: gradle build and tests were not executed (no Android SDK on this machine, per the brief); correctness is by inspection only — the `animateScrollToItem(index, scrollOffset, animationSpec)` overload was verified against the project's Compose BOM 2024.02.00 (foundation 1.6.x, overload available since 1.4). CI must confirm compilation.
- The springy feel (stiffness/damping tuning, 300ms emphasis timing) has not been eyeballed on a device; values follow the addendum's spec but may want tuning after a real playback session.
